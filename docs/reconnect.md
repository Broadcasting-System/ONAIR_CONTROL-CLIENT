# 송출 소켓 다시 붙기

송출 미리보기(`useDisplaySync`)와 송출 화면(onair-display `useWebSocket`)은 `useReconnectingSocket`
(`src/lib/reconnectingSocket.ts`, 송출 화면 저장소 `lib/reconnectingSocket.ts` 와 같은 코드)으로 서버에 붙는다.

## 규칙

- 끊기면 **지수 백오프 + 지터**로 다시 붙는다. 1초부터 두 배씩, 최대 10초. 실제 기다리는 시간은 그 상한의 절반~상한 사이
  아무 값(equal jitter).
- **상태 맞추기는 서버가 한다.** 붙자마자 서버가 그 채널의 지금 상태를 보낸다(대기 중이면 standby). 그래서 끊긴 동안 놓친
  메시지를 따로 받지 않는다.
- 서버의 첫 메시지를 받아야 '붙었다'로 보고 간격을 처음으로 돌린다. 열리자마자 닫히는 서버에 가장 짧은 간격으로 계속
  두드리지 않게.
- 주소가 바뀌면(채널 변경) 옛 소켓은 닫고 다시 붙지 않는다. 늦게 온 옛 메시지도 버린다.
- 기기 네트워크가 돌아오면(`online` 이벤트) 기다리지 않고 바로 붙는다.
- `status`(connecting·open·reconnecting)와 `staleSince`(끊긴 시각)를 돌려준다. 컨트롤 미리보기는 끊긴 동안
  LIVE MONITOR 자리에 '연결 끊김 · N초 전 화면'을 보인다. 송출 화면 자체에는 보이지 않는다(전교에 나가는 화면이라).

## 왜 백오프·지터인가 — 모의 실험

`node scripts/sim-reconnect-herd.mjs`. 화면 300개(live 시청 학생 규모)가 서버 재시작으로 한꺼번에 끊기는 상황.
서버가 꺼져 있는 동안 시도는 바로 실패한다고 보고, 시도 시각을 100ms 칸으로 세었다.

| 서버 꺼짐 | 방식 | 접속 시도 합 | 100ms 당 최대 | 서버가 돌아온 뒤 화면 복귀 (중앙 / 최대) |
|---|---|---|---|---|
| 2초 | 고정 3초 (전) | 300 | 300 | 1.0초 / 1.0초 |
| 2초 | equal 1~10초 (지금) | 657 | 68 | 0.5초 / 3.9초 |
| 15초 | 고정 3초 (전) | 1,500 | 300 | 0~3초 (3초 주기와 겹치는 정도에 따라) |
| 15초 | equal 1~10초 (지금) | 1,509 | 76 | 3.7초 / 8.9초 |
| 60초 | 고정 3초 (전) | 6,000 | 300 | 0~3초 |
| 60초 | equal 1~10초 (지금) | 3,300 | 64 | 3.9초 / 9.1초 |

- 고정 간격은 모두가 같은 순간에 끊겼으므로 **3초마다 300개가 같은 순간에** 몰린다. 지터로 흩으면 100ms 당 최대가 약 1/4.
- 대신 서버가 돌아온 뒤 화면이 돌아오는 데 최대 10초까지 걸린다(전에는 3초 이내). 상한을 30초로 하면 시도는 더 줄지만 복귀가
  최대 29초라 송출 화면에는 길다고 보고 10초로 했다.
- full jitter(0~상한)는 몰림이 더 적지만 아주 짧은 간격이 자주 나와 시도 합이 늘었다.
- 시작 간격 0.5초는 짧은 끊김에서 조금 빨리 돌아오지만 첫 시도 칸이 좁아 몰림이 약 2배(137)라 1초로 했다.

늘림, 상태·끊긴 시각, 채널 변경, online, heartbeat.
