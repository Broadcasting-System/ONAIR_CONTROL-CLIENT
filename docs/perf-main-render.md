# 메인 화면 렌더 측정 (React Profiler)

방송실 PC 는 메인 화면(`/main`)을 하루 종일 켜 둔다. 아무도 만지지 않아도 폴링이 5~10초마다 돌아온다.

## 측정

`src/app/(dashboard)/main/page.profile.test.tsx` — `MEASURE=1 pnpm vitest run main/page.profile --silent=false`

- 조건: Vitest + jsdom, 가짜 타이머로 **아무것도 바뀌지 않는 60초**. 서버 응답 고정 — 스피커 상태 그대로, 응답 시간(latency)만
  매번 조금씩 다름(실제 서버도 그렇다). 구역 58개(학교와 같은 수).
- 방송 칸(BroadcastCard)·방송 모니터(DisplayMirror)는 렌더 횟수만 세는 가짜로 바꿨다 → 아래 ms 에는 이 둘의 렌더 비용이
  **빠져 있다**(실제로는 더 크다).
- `<Profiler onRender>` 로 커밋 수와 actualDuration 합, 컴포넌트별 렌더 횟수를 셌다. 5번 돌려 같은 값(ms 만 ±1).

| | 커밋 | 렌더 시간 합(jsdom) | 방송 칸 | 방송 모니터 | 스피커 칸(StatusCard) |
|---|---|---|---|---|---|
| 전 | 24 | 58~59ms | 24 | 24 | 1,392 (58 × 24) |
| 페이지 나누기만 | 24 | 31ms | 0 | 0 | 696 |
| 지금 (+ 같은 상태면 안 넣기) | **12** | **3~4ms** | **0** | **0** | **0** |

jsdom 의 ms 는 실제 브라우저와 다르다(레이아웃·페인트 없음). 비교용으로만 본다. 횟수는 브라우저에서도 같다.

## 원인

1. **페이지 전체가 모든 폴링을 구독**: `MainPage` 한 컴포넌트가 스피커(5초)·응답 시간(5초)·송출 상태(10초)·강당 장비(10초)를
   모두 불러서, 무엇이 돌아오든 페이지 전체 — 방송 칸(TTS·마이크), 방송 모니터(영상 요소), 스피커 58칸 — 를 다시 그렸다.
2. **바뀐 게 없어도 새 배열**: `useSpeakers` 가 5초마다 같은 상태로 새 배열을 만들어 스토어에 넣었다. Zustand 는 참조가 다르면
   바뀐 것으로 본다. 게다가 스토어 전체를 구독(`useSpeakerStore()`)하고 있었다.

TanStack Query 쪽(송출 상태·강당 장비)은 응답이 같으면 이전 객체를 그대로 돌려줘서(structural sharing) 다시 그리지 않았다.
그래서 24 = 스피커 12 + 응답 시간 12.

## 고친 것

- 메인을 칸으로 나눴다: `NetworkSection`(응답 시간·송출 상태·강당 장비), `SpeakerSection`(스피커). 페이지 자체는 훅이 없어
  폴링으로 다시 그려지지 않는다(state colocation). `React.memo` 를 여기저기 붙이는 것보다 데이터를 쓰는 곳으로 내리는 쪽이
  단순하고 깨지기 어렵다.
- `useSpeakers`: 폴링 결과가 지금과 같으면(구역·이름·켜짐) 스토어에 넣지 않는다. 스토어는 `zones`·`setZones` 만 골라 구독.

남은 12번은 응답 시간 카드가 실제로 바뀌는 것(5초마다 ms 값)이라 그대로 둔다 — 네트워크 상태 칸만 다시 그린다.

## 시험

- 바뀐 게 없는 1분: 방송 칸·모니터·스피커 칸 0번, 커밋 12번 이하 (렌더 예산 — 다시 늘면 CI 에서 실패)
- 스피커 상태가 바뀌면 스피커 칸 58개는 다시 그리고 방송 칸·모니터는 그대로, ON 이 3개
